# FrostbiteUniversal SDK Bridge Template

This template shows how to connect `FrostbiteUniversal.dll` to an SDK you already generated for an owned Frostbite project.

The Universal DLL does not know your game's C++ classes by itself. It talks to your project through a small bridge with exported functions. This template gives you that bridge shape, so the only custom work is mapping your SDK types to the Universal structs.

## What You Get

```text
Templates/FrostbiteUniversalSdkBridge/
  CMakeLists.txt
  FrostbiteUniversal_Bridge.ini
  include/
    FrostbiteUniversalSdkBridge.h
    SdkBindings.h
  src/
    FrostbiteUniversalSdkBridge.cpp
    SdkBindings.cpp
```

| File | Purpose |
| --- | --- |
| `FrostbiteUniversalSdkBridge.cpp` | Exports the exact `FrostbiteGame_*` functions Universal can auto-detect. Usually you do not edit this file. |
| `SdkBindings.h/.cpp` | Your project-specific adapter. This is where you connect your generated SDK, actor list, timescale, sky/environment, and debug material systems. |
| `FrostbiteUniversal_Bridge.ini` | Sample config for telling Universal which module and exports to use. |
| `FrostbiteUniversalSdkBridge.sln` | Visual Studio solution for building the bridge DLL without CMake. |
| `CMakeLists.txt` | Optional CMake build for users who prefer it. |

## Step 1: Have Your Generated SDK Ready

After running the SDK generator, the SDK usually lives under:

```text
GeneratedSDK/Injected_<process>_<pid>/SDK/
```

The common include entry point is:

```cpp
#include "SDK/SDK.hpp"
```

or, if your include directory points directly at the `SDK` folder:

```cpp
#include "SDK.hpp"
```

## Step 2: Choose How To Build The Bridge

### Option A: Compile Into Your Owned Game

Use this when you control the game project and can add files to the executable.

1. Add these files to your project:
   - `include/FrostbiteUniversalSdkBridge.h`
   - `include/SdkBindings.h`
   - `src/FrostbiteUniversalSdkBridge.cpp`
   - `src/SdkBindings.cpp`
2. Add these include directories:
   - `Templates/FrostbiteUniversalSdkBridge/include`
   - `Source/FrostbiteUniversal/Include`
   - `GeneratedSDK/Injected_<process>_<pid>/SDK` or the parent dump folder
3. Leave `ModuleName=` blank in `FrostbiteUniversal_Bridge.ini`.

### Option B: Build A Bridge DLL In Visual Studio

Use this when you prefer a separate project-owned DLL.

1. Open:

   ```text
   Templates/FrostbiteUniversalSdkBridge/FrostbiteUniversalSdkBridge.sln
   ```

2. Select `Release`.
3. Select `x64`.
4. Build.

Output:

```text
Templates/FrostbiteUniversalSdkBridge/build/x64/Release/FrostbiteUniversalSdkBridge.dll
```

The project has a `GeneratedSdkDir` property that defaults to:

```text
GeneratedSDK/Example/SDK
```

To point it at your generated SDK, right-click the project, open **Properties**, and update:

```text
C/C++ -> General -> Additional Include Directories
```

or edit `FrostbiteUniversalSdkBridge.vcxproj` and set:

```xml
<GeneratedSdkDir>C:\Path\To\GeneratedSDK\Injected_<process>_<pid>\SDK</GeneratedSdkDir>
```

### Option C: Optional CMake Build

Use this if you prefer CMake.

```powershell
cmake -S ".\Templates\FrostbiteUniversalSdkBridge" `
  -B ".\Templates\FrostbiteUniversalSdkBridge\build" `
  -A x64 `
  -DFROSTBITE_UNIVERSAL_INCLUDE_DIR="C:\Path\To\Frostbite-Universal\Source\FrostbiteUniversal\Include" `
  -DGENERATED_SDK_DIR="C:\Path\To\GeneratedSDK\Injected_<process>_<pid>\SDK" `
  -DAEGIS_TEMPLATE_ENABLE_SAMPLE_DATA=ON

cmake --build ".\Templates\FrostbiteUniversalSdkBridge\build" --config Release
```

Then make sure your owned game loads `FrostbiteUniversalSdkBridge.dll` through its normal plugin/module path. Set:

```ini
ModuleName=FrostbiteUniversalSdkBridge.dll
```

in the config file next to `FrostbiteUniversal.dll`.

## Step 3: Edit `SdkBindings.cpp`

Open:

```text
Templates/FrostbiteUniversalSdkBridge/src/SdkBindings.cpp
```

Replace the marked adapter functions with your SDK calls:

| Template Function | Connect It To |
| --- | --- |
| `GetActorModelCount` | Your world/entity list count |
| `GetActorModel` | Your actor/component/model data |
| `SetTimescale` | Your owned engine's time scale setter |
| `GetTimescale` | Your owned engine's time scale getter |
| `ApplySkyboxTint` | Your sky/environment system |
| `ApplyModelDebugTint` | Your debug material or editor visualization system |
| `ApplyFogTint` | Your fog/atmosphere/environment system |
| `ReadFeatureState` | Current values from your engine, if available |

Keep `FrostbiteUniversalSdkBridge.cpp` mostly unchanged. It is the stable exported API layer.

## Actor / Model Location And Size Cache

The template stores visible actors/models in a normal array:

```cpp
std::vector<ActorModel> g_actorModels;
```

Each entry contains:

```cpp
struct ActorModel
{
    std::uint64_t id;
    std::wstring actorName;
    std::wstring className;
    std::wstring modelName;
    std::wstring assetPath;
    Vector3 position;
    Vector3 rotationEuler;
    Vector3 scale;
    Bounds3 bounds;       // min, max, size, center, radius
    ScreenRect screen;    // optional 2D projection for boxes/snaplines
    std::uint32_t flags;
};
```

`FrostbiteUniversal` displays the important parts in the Project tab:

- position
- size
- radius
- optional 2D debug box
- optional snapline point
- actor name
- class name
- model name
- asset path

The function to customize is:

```cpp
RefreshActorModelCacheLocked()
```

Inside that function, replace the sample rows with your generated SDK traversal. The names below are placeholders because each generated SDK names wrappers differently, but this is the exact shape you want:

```cpp
g_actorModels.clear();

auto* world = YourSdk::GetGameWorld();
if (!world)
    return;

for (auto* entity : world->Entities())
{
    if (!entity)
        continue;

    auto* transform = entity->GetTransformComponent();
    auto* render = entity->GetRenderComponent();
    auto* model = render ? render->GetModel() : nullptr;
    if (!transform || !model)
        continue;

    ActorModel item = {};
    item.id = entity->GetStableId();
    item.actorName = entity->GetNameW();
    item.className = entity->GetTypeNameW();
    item.modelName = model->GetNameW();
    item.assetPath = model->GetAssetPathW();

    item.position = {
        transform->WorldPosition().x,
        transform->WorldPosition().y,
        transform->WorldPosition().z
    };

    item.rotationEuler = {
        transform->WorldRotationEuler().x,
        transform->WorldRotationEuler().y,
        transform->WorldRotationEuler().z
    };

    item.scale = {
        transform->WorldScale().x,
        transform->WorldScale().y,
        transform->WorldScale().z
    };

    item.bounds = MakeBoundsFromMinMax(
        {
            model->WorldBoundsMin().x,
            model->WorldBoundsMin().y,
            model->WorldBoundsMin().z
        },
        {
            model->WorldBoundsMax().x,
            model->WorldBoundsMax().y,
            model->WorldBoundsMax().z
        });

    item.flags = FrostbiteActorModel_Actor |
        FrostbiteActorModel_Model |
        FrostbiteActorModel_Dynamic |
        FrostbiteActorModel_Visible |
        FrostbiteActorModel_FromProvider;

    if (camera->ProjectWorldBounds(item.bounds, item.screen))
        item.flags |= FrostbiteActorModel_HasScreenProjection;

    g_actorModels.push_back(std::move(item));
}
```

If your SDK only gives center position and local dimensions, use:

```cpp
item.bounds = MakeBoundsFromCenterSize(item.position, { width, height, depth });
```

If your SDK exposes a camera projection helper, fill `ScreenRect` like this:

```cpp
item.screen.centerX = projectedCenter.x;
item.screen.centerY = projectedCenter.y;
item.screen.minX = projectedBoxMin.x;
item.screen.minY = projectedBoxMin.y;
item.screen.maxX = projectedBoxMax.x;
item.screen.maxY = projectedBoxMax.y;
item.screen.depth = projectedDepth;
item.screen.valid = true;
item.flags |= FrostbiteActorModel_HasScreenProjection;
```

When Universal calls `Refresh Actors/Models`, the bridge refreshes `g_actorModels`, then Universal asks for each row through:

```cpp
FrostbiteGame_GetActorModelCount();
FrostbiteGame_GetActorModelInfo(index, &outInfo);
```

`FrostbiteGame_GetActorModelInfo` copies your cached `ActorModel` into `FrostbiteActorModelInfo`, including position, rotation, scale, bounds min/max, size, radius, and optional screen projection.

## Built-In Feature Example

Before you connect a real SDK, the template keeps an in-memory feature backend so users can see the Universal controls working:

| Universal Control | Template Behavior |
| --- | --- |
| `Timescale` | Stores a clamped value from `0.01` to `20.0` and recomputes `scaledFrameDelta = 1/60 * timescale`. |
| `Skybox color/intensity` | Stores a live skybox tint preview and updates the sample `Template_Skybox_Intensity_*` actor row. |
| `Fog color/density` | Stores a live fog preview and updates the sample `Template_Fog_Density_*` actor row. |
| `Debug material tint` | Stores debug material tint state for users to map to their editor/debug renderer. |
| `Refresh Actors/Models` | Shows sample rows for `Sdk::TimeSystem`, `Sdk::VisualEnvironment`, and `Sdk::FogComponent`, including position, size, and radius. |
| `Draw model boxes` | Draws ImGui rectangles from `ActorModel::screen` when `FrostbiteActorModel_HasScreenProjection` is set. |
| `Draw snaplines` | Draws ImGui lines from the bottom-center of the viewport to each projected model center. |
| `FOV override` | Stores a clamped camera FOV and calls the optional `setFov` callback. |
| `View-angle preview` | Computes a look-at pitch/yaw/roll from a target model position and calls the optional `setViewAngles` callback. |

Once your real SDK is wired, turn the sample rows off:

```powershell
cmake -S ".\Templates\FrostbiteUniversalSdkBridge" `
  -B ".\Templates\FrostbiteUniversalSdkBridge\build" `
  -A x64 `
  -DFROSTBITE_UNIVERSAL_INCLUDE_DIR="C:\Path\To\Frostbite-Universal\Source\FrostbiteUniversal\Include" `
  -DGENERATED_SDK_DIR="C:\Path\To\GeneratedSDK\Injected_<process>_<pid>\SDK" `
  -DAEGIS_TEMPLATE_ENABLE_SAMPLE_DATA=OFF
```

## Fast Callback Wiring

If you compile the template directly into your owned game, you can register callbacks instead of editing every TODO immediately:

```cpp
#include "SdkBindings.h"

namespace Bridge = Aegis::FrostbiteUniversalTemplate::Sdk;

static void SetGameTimescale(void* userData, float timescale)
{
    auto* game = static_cast<MyOwnedGame*>(userData);
    game->GetTimeSystem()->SetTimescale(timescale);
}

static bool GetGameTimescale(void* userData, float* outTimescale)
{
    if (!outTimescale)
        return false;

    auto* game = static_cast<MyOwnedGame*>(userData);
    *outTimescale = game->GetTimeSystem()->GetTimescale();
    return true;
}

static void SetSkyboxTint(void* userData, const Bridge::Color4* color, float intensity)
{
    auto* game = static_cast<MyOwnedGame*>(userData);
    game->GetEnvironment()->SetSkyboxTint(color->r, color->g, color->b, intensity);
}

static void SetFogTint(void* userData, bool enabled, const Bridge::Color4* color, float density)
{
    auto* game = static_cast<MyOwnedGame*>(userData);
    game->GetEnvironment()->SetFogTintEnabled(enabled);
    game->GetEnvironment()->SetFogTint(color->r, color->g, color->b, density);
}

static void SetFov(void* userData, float fovDegrees)
{
    auto* game = static_cast<MyOwnedGame*>(userData);
    game->GetCamera()->SetFovDegrees(fovDegrees);
}

static void SetViewAngles(void* userData, const Bridge::Vector3* angles, const Bridge::Vector3* targetPosition)
{
    if (!angles)
        return;

    auto* game = static_cast<MyOwnedGame*>(userData);
    game->GetDebugCamera()->SetPreviewViewAngles(angles->x, angles->y, angles->z);

    if (targetPosition)
        game->GetDebugCamera()->SetPreviewLookAt(targetPosition->x, targetPosition->y, targetPosition->z);
}

void InstallUniversalBridgeCallbacks(MyOwnedGame* game)
{
    Bridge::RuntimeFeatureCallbacks callbacks = {};
    callbacks.userData = game;
    callbacks.setTimescale = SetGameTimescale;
    callbacks.getTimescale = GetGameTimescale;
    callbacks.setSkyboxTint = SetSkyboxTint;
    callbacks.setFogTint = SetFogTint;
    callbacks.setFov = SetFov;
    callbacks.setViewAngles = SetViewAngles;
    Bridge::SetRuntimeFeatureCallbacks(callbacks);
}
```

If you build the template as a separate DLL, edit `SdkBindings.cpp` and replace the TODO sections with your SDK calls instead.

## Step 4: Configure Universal

Place this file beside `FrostbiteUniversal.dll`:

```text
FrostbiteUniversal_Bridge.ini
```

If `ModuleName=` names a bridge DLL and that DLL is beside `FrostbiteUniversal.dll`, Universal will explicitly load that bridge module before resolving exports. This makes a local one-folder test setup possible:

```text
TestBundle/
  INJECT_THIS_FrostbiteUniversal.dll
  FrostbiteUniversalSdkBridge.dll
  FrostbiteUniversal_Bridge.ini
```

Use the template config:

```ini
[BridgeExports]
ModuleName=FrostbiteUniversalSdkBridge.dll
GetActorModelCount=FrostbiteGame_GetActorModelCount
GetActorModelInfo=FrostbiteGame_GetActorModelInfo
SetTimescale=FrostbiteGame_SetTimescale
GetTimescale=FrostbiteGame_GetTimescale
ApplyFeatures=FrostbiteGame_ApplyUniversalFeatures
GetFeatureState=FrostbiteGame_GetUniversalFeatureState
SetSkyboxTint=FrostbiteGame_SetSkyboxTint
SetDebugMaterialTint=FrostbiteGame_SetDebugMaterialTint
SetFogTint=FrostbiteGame_SetFogTint
```

If you compiled the bridge directly into your EXE, set:

```ini
ModuleName=
```

## Step 5: Test In Universal

1. Start your owned project.
2. Load `FrostbiteUniversal.dll` through your local test/plugin flow.
3. Open the Universal ImGui panel.
4. Go to the `Project` tab.
5. Press `Refresh Bridge Status`.
6. Confirm:
   - Actor/model bridge: `connected`
   - Timescale bridge: `connected`
   - Feature bridge: `connected`
7. Press `Refresh Actors/Models` to populate the live list.
8. Try `Sync` to read the current timescale.
9. Try `Apply Timescale` or `Apply Features`.

If a section says `local-only`, Universal could not find the matching export. Check `ModuleName`, export names, calling convention, and whether your bridge module is loaded.

## Export Signatures

The exported signatures must stay exactly compatible:

```cpp
std::uint32_t __stdcall FrostbiteGame_GetActorModelCount();
int __stdcall FrostbiteGame_GetActorModelInfo(std::uint32_t index, FrostbiteActorModelInfo* outInfo);
void __stdcall FrostbiteGame_SetTimescale(float timescale);
float __stdcall FrostbiteGame_GetTimescale();
int __stdcall FrostbiteGame_ApplyUniversalFeatures(const FrostbiteUniversalFeatureState* state);
int __stdcall FrostbiteGame_GetUniversalFeatureState(FrostbiteUniversalFeatureState* outState);
void __stdcall FrostbiteGame_SetSkyboxTint(float r, float g, float b, float intensity);
void __stdcall FrostbiteGame_SetDebugMaterialTint(int enabled, float r, float g, float b, float opacity);
void __stdcall FrostbiteGame_SetFogTint(int enabled, float r, float g, float b, float density);
void __stdcall FrostbiteGame_SetFov(float fovDegrees);
void __stdcall FrostbiteGame_SetViewAngles(float pitch, float yaw, float roll);
```

The template already exports these for you. It also exports the older `FrostbiteGame_SetChams` name as a compatibility alias for existing local configs.

## Common Fixes

### Universal says not connected

- `FrostbiteUniversal_Bridge.ini` is not beside `FrostbiteUniversal.dll`.
- `ModuleName` points at a DLL that is not loaded.
- The export names do not match.
- The exports are missing `extern "C"`.
- The calling convention is not `__stdcall`.
- The bridge was built as x86 instead of x64.

### Actor list is empty

- `GetActorModelCount` returns zero.
- `GetActorModel` returns false/zero.
- Your SDK adapter is reading editor-only data while the level is not loaded.
- Your owned project has not initialized the world/entity system yet.

### Timescale does not change

- The adapter still uses the template fallback variable.
- Your SDK exposes read-only metadata, not callable runtime wrappers.
- Your engine time system has a different per-world or per-scene timescale.
- The feature flag `FrostbiteFeature_Timescale` is not enabled when using `Apply Features`.

## Important Boundary

Use this only with projects you own or have permission to inspect and instrument. The bridge should call your own engine/API wrappers and should not bypass anti-cheat, evade protections, decrypt protected files, or patch third-party process memory.
